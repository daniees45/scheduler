═══════════════════════════════════════════════════════════════════
  WHAT HAPPENS AFTER EACH SCHEDULE GENERATION?
═══════════════════════════════════════════════════════════════════

1. SAVE LOCALLY  
   ├─ Final: generated_schedule_YYYYMMDD_HHMMSS.csv
   └─ Outputs ready for use

2. CREATE TWO HISTORICAL FILES (Hybrid Approach)
   ├─ Timestamped: historical_schedule_YYYYMMDD_HHMMSS.csv
   │  └─ Purpose: Version control, rollback, tracking
   └─ Master: historical_schedule.csv (APPENDED)
      └─ Purpose: Training data (all generations combined)

3. UPLOAD TO B2 CLOUD (3 files per generation)
   ├─ Final: csv/final/schedule_YYYYMMDD_HHMMSS.csv
   ├─ Timestamped: csv/history/historical_schedule_YYYYMMDD_HHMMSS.csv
   └─ Master: csv/general/historical_schedule.csv (updated)

4. RETRAIN AI MODELS (using master file)
   ├─ Q-Learning Model (q_model.pkl)
   ├─ Feasibility Classifier (feasibility_classifier.pkl)
   └─ Scheduling Model (scheduling_model.pkl)

5. UPLOAD MODELS TO B2
   └─ All models uploaded to root of bucket

═══════════════════════════════════════════════════════════════════
  HYBRID SYSTEM BENEFITS
═══════════════════════════════════════════════════════════════════

✅ VERSION CONTROL: Timestamped files track each generation
✅ EASY TRAINING: Master file has all data in one place
✅ CLEAN DATA: No timestamp columns cluttering CSVs
✅ FLEXIBLE CLEANUP: Delete old timestamped files safely
✅ ROLLBACK: Load any specific generation
✅ DUAL BACKUP: Both files uploaded to B2

   wc -l historical_schedule.csv

   ls -t historical_schedule_*.csv | tail -n +21 | xargs rm
   # Master file unchanged - keeps all training data

📄 VIEW SPECIFIC GENERATION:
   head -n 20 historical_schedule_20260221_143022.csv
